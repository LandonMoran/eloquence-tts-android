# Generated artifacts and source-of-truth contract

Some tracked files are generated outputs. Change their authoritative inputs
and run the generator instead of editing the outputs by hand. Otherwise, the
next generation may overwrite the edit or CI may fail.

## Sources of truth

- `oracle/table/*.consolidated.tsv` contains the consolidated Chinese audio
  rows used by the generator.
- `oracle/corpus/` contains acquisition and validation material; edits there
  do not automatically become rows in the generated oracle C file.
- Application, native, and generator source files are maintained directly,
  except for explicitly generated outputs such as `oracle_chs.c`.

## Generated files

- `native/openevv/lang/chs/oracle_chs.c` is generated by
  `oracle/merge_build.py` from the consolidated TSV files and compatible legacy
  rows in the existing C source. It includes phoneme and audio lookup data.
- `language-models/models.elqm` and the Lingua bridge are generated or
  verified by `tools/prepare_assets.py`.

## Updating generated data

For Chinese oracle table changes, update the consolidated source table and
regenerate to a temporary file for comparison:

```sh
python3 oracle/merge_build.py oracle/table \
  native/openevv/lang/chs/oracle_chs.c /tmp/oracle_chs.c
python3 oracle/check_gbk_gate.py /tmp/oracle_chs.c
```

Review the output before replacing the tracked generated file. The native
build workflow also regenerates the oracle source and checks the GBK gate.
For packaged language-model assets, use
`python3 tools/prepare_assets.py --verify` to check reproducibility.

Generated files should match their inputs deterministically. Include the
source changes and reviewed generated outputs together when a generated
artifact changes.
